# 消息事件触发任务

目标：用户配置来源群、发送人、被提及对象、关键词及预设指令；匹配的新消息自动形成独立持久任务，交给现有 coding agent 执行。

实现选择：复用 SQLAlchemy 数据库和 daemon 串行消费队列；只增加规则表和来源消息/现有 Task 的去重关联表，不增加执行系统。周期扫描已入库消息，保证消息入库后中途失败不丢事件。规则创建/重新启用以当前时间为起点；唯一键 rule_id/chat_id/msg_id 去重。任务开始前再次检查规则启用状态。执行中重启标记 unknown，不自动重试，避免重复副作用。来源消息以 JSON 数据嵌入，预设指令单独提供。普通 /ai 触发政策不变。仅允许本人交互会话管理规则，访客与事件任务不能管理。

- [x] 全量 pytest 与独立异常场景复核；默认不创建启用规则、不部署未验证版本。

范围：文本消息事件；不做 UI；不引入依赖。所有规则默认排除本人消息以阻断自回环，可显式指定本人；生成的消息通过审计记录排除。用户未确定发送人范围，示例不替用户启用实际规则。


## 实际验证

- `.venv/bin/python -m pytest -q tests`：245 passed, 1 skipped。
- 独立异常探针：暂停与认领交错、暂停与扫描交错、调度快照与暂停交错、执行异常、事务中途失败、长任务阻塞期间重复 tick。
- 已修复：认领读后暂停仍执行、扫描读后暂停仍生成旧任务、调度旧快照复活任务、异常后永久 running。各项都有真实 SQLite/Daemon 回归用例，先失败再通过。
- 去掉扫描锁、认领条件、调度条件及异常结算守卫的四个独立进程变异测试均失败，生产代码未被变异。
- 原定时任务、普通消息与访客权限回归通过。共用 Task 调度，适用于 Codex/Claude；无新增 macOS/Linux 特有依赖。外部飞书真实 @和两个群的端到端任务执行仍待用户验证。

实施选择：仅增加规则与 Task 关联，不增加独立执行表。未自动创建/启用实际规则；发送人范围由本人确认。命令/手册已实现，按自然语言配置需要现有 agent 完成身份解析与草稿确认。
